# Sheet: to do

Нативний офлайн-застосунок для Android на Expo SDK 57, React Native, Expo Router і
TypeScript.

## Можливості

- кілька незалежних списків із назвою та однією з 12 тематичних іконок;
- додавання, виконання й видалення завдань;
- лічильник і прогрес виконання;
- вибір, стиснення, перегляд і видалення локальних фото;
- чотири оригінальні фонові теми та власний локальний фон із системного photo picker;
- автоматичне локальне збереження та міграція формату даних;
- українська й англійська локалізації;
- sharing читабельного тексту, JSON, deep link або ZIP-пакета з фотографіями;
- захищений імпорт ZIP/JSON, deep link і старого формату вебверсії;
- повністю офлайн-робота без реєстрації, аналітики, реклами або сервера.

## Архітектура

- `src/app` — маршрути Expo Router: головний екран і підтвердження deep-link імпорту;
- `src/components` — картки списків, рядки завдань і нативні модальні вікна;
- `src/domain` — типи `Task`, `TaskList`, незмінні операції та міграції даних;
- `src/state` — невеликий React Context, який координує UI, сховище й файли;
- `src/services` — AsyncStorage, Expo FileSystem, photo picker, JSON/deep-link і ZIP transfer;
- `src/i18n` і `src/theme` — локалізації, іконки та локальні фонові теми;
- `assets` — оригінальні локальні PNG без CDN.

Структура даних навмисно проста. AsyncStorage містить лише JSON із метаданими, а
фотографії зберігаються окремими JPEG-файлами в document directory застосунку.

## Встановлення залежностей

Потрібен Node.js 22.13 або новіший і npm.

```powershell
npm install
```

Корисні перевірки:

```powershell
npm run lint
npm run typecheck
npm test
npm run doctor
npm run format:check
```

## Запуск через Expo Go

```powershell
npm start
```

Відкрий актуальний Expo Go з підтримкою SDK 57 на Android і відскануй QR-код. Усі
використані API входять до Expo Go. Якщо магазин застосунків ще не пропонує сумісний
Expo Go під час переходу SDK, скористайся development build.

## Запуск development build

Профіль `development` уже є в `eas.json`, а `expo-dev-client` встановлено.

```powershell
npx eas-cli@latest build --platform android --profile development
npm run dev
```

Перший рядок створює development APK через EAS. Встанови його з посилання/QR-коду,
після чого development client під’єднається до Metro з другого рядка.

## Створення APK

Профіль `preview` має `distribution: internal` і `android.buildType: apk`:

```powershell
npx eas-cli@latest build --platform android --profile preview
```

Після завершення відкрий build URL, завантаж APK і збережи його як
`dist/sheet-to-do-0.2.0.apk`. Папка `dist` ігнорується Git. Контрольна сума у Windows:

```powershell
Get-FileHash dist\sheet-to-do-0.2.0.apk -Algorithm SHA256
```

Перевірена preview-збірка 0.2.0 (versionCode 2) завершена в
[EAS Build](https://expo.dev/accounts/sugar4vaders-team/projects/sheet-to-do/builds/61c084ab-c254-424e-9582-bb52837a2511).
Локальний APK має розмір `107559437` байтів і SHA-256
`DF762566123B4B15544F065EBD9C5D1F34CC297DDF615F828025BABD6E8CEF13`.

Профіль `production` залишено для майбутнього AAB; він не публікує застосунок у Google
Play автоматично.

Локальна Gradle-збірка потребує Android SDK, platform-tools, build-tools і сумісного
JDK. Після їх встановлення можна виконати `npx expo prebuild --platform android`, а
потім збирати native-проєкт. Для підписаного інсталяційного APK рекомендований EAS,
який безпечно керує Android keystore.

## Встановлення APK на Android

1. Передай `sheet-to-do-0.2.0.apk` на телефон через Telegram, Drive, USB або інший канал.
2. Відкрий файл у системному файловому менеджері.
3. Якщо Android попросить, дозволь цьому файловому менеджеру встановлювати невідомі
   застосунки. Не вмикай дозвіл для непотрібних програм.
4. Перевір назву “Sheet: to do” і натисни **Встановити**.
5. Після інсталяції можна вимкнути дозвіл “Встановлення невідомих застосунків”.

Детальніше: [docs/ANDROID_INSTALL.md](docs/ANDROID_INSTALL.md).

## Оновлення вже встановленої версії

Збирай новий APK із тим самим package `com.lilydotsenko.sheettodo`, тим самим signing
key і більшим `android.versionCode`. Встанови APK поверх попередньої версії — списки й
локальні фотографії залишаться. Android відхилить оновлення, якщо підпис відрізняється;
у такому разі спершу експортуй важливі списки, а видалення старої версії залиш на
крайній випадок.

## Резервне копіювання й перенесення списків

У картці списку натисни кнопку sharing і вибери:

- **Як звичайний текст** — назва, прогрес і checklist для людини; назад не імпортується;
- **ZIP-пакет із фото** (`.sheet-to-do.zip`) — повна офлайн-копія для версії 0.2.0+;
- **JSON-файл** — сумісний із 0.1.0 резервний формат без фотографій;
- **Deep link** — `sheettodo:///import?data=...` для невеликих списків без фото.

На іншому пристрої обери ZIP або JSON кнопкою **Імпорт**, або відкрий deep link після
встановлення застосунку. ZIP містить versioned `manifest.json` та окремі JPEG у
`photos/`; base64 не використовується. Імпорт перевіряє версію, CRC32, розміри,
кількість, типи, безпечні шляхи та відповідність manifest. Нові ID створюються завжди,
а фото транзакційно копіюються в приватну директорію. Частково відсутні заявлені фото
пропускаються з попередженням; пошкоджені, надмірні чи небезпечні архіви відхиляються.

Для ZIP використано `fflate` 0.8.x (MIT): це невелика pure-JavaScript бібліотека з
TypeScript-типами, без native-модуля, сервера чи нових Android permissions. Її filter API
дозволяє перевірити імена та заявлені розміри записів до розпакування.

## Структура локальних даних

- ключ AsyncStorage: `sheet-to-do:data`;
- поточна версія локальних даних: `2` (міграція з v1 автоматична);
- списки: ID, назва, icon ID, дата створення й масив завдань;
- завдання: ID, текст, стан, дата й необов’язкові метадані JPEG;
- preferences: стандартний theme ID, метадані власного локального фону та мова;
- фото: document directory `task-photos`, максимум 1600 px по довшій стороні, JPEG 0.76;
- власний фон: document directory `custom-backgrounds`, максимум 2400 px, JPEG 0.82;
- пошкоджений payload відкладається під ключ `sheet-to-do:data:corrupt`, після чого
  застосунок запускається з чистим сховищем.

Файл фотографії видаляється разом із фото, завданням або списком. Якщо Android уже
видалив/втратив файл, застосунок прибере застарілі метадані без аварійного завершення.

## Дозволи Android

Застосунок не просить доступ до геолокації, контактів, мікрофона або камери. `CAMERA` і
`RECORD_AUDIO` явно заблоковані в `app.json`. Вибір фото, ZIP і JSON відбувається через
системні picker-и, тому широкого доступу до медіатеки або файлової системи не потрібно.
Share Sheet відкривається лише після натискання користувача.

## Відомі обмеження

- JSON і deep links не містять фотографій; повне перенесення потребує ZIP та версії 0.2.0+;
- власний фон не входить до експорту списку й залишається налаштуванням пристрою;
- немає cloud sync: резервні копії створює користувач;
- застосунок орієнтований на Android 7+ відповідно до Expo SDK 57;
- npm audit наразі показує moderate advisory у транзитивному build-time ланцюжку
  Expo config plugins (`xcode` → `uuid`). Expo Doctor проходить 20/20; автоматичний
  `npm audit fix --force` не застосовується, бо він замінює SDK-сумісні Expo packages
  несумісними major-версіями.

Походження та статус кожного візуального файла описано в
[docs/ASSET_SOURCES.md](docs/ASSET_SOURCES.md).
